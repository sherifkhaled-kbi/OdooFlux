# Data Model: Version Compatibility Rules

Rule metadata follows the schema defined by feature 004
(`knowledge/schemas/rule_metadata.schema.json`) and the Rule contract in
[CONTRACTS.md](../../docs/planning/architecture/CONTRACTS.md#rule).

## RuleMetadata (one entry in `knowledge/compatibility/<step>.rules.json`)

```json
{
  "id": "17-18.python.group-operator-renamed",
  "step": "17-18",
  "file_kinds": ["python"],
  "severity": "WARNING",
  "maturity": "FIX_ENABLED",
  "review_required": false,
  "ai_eligible": false,
  "evidence": ["EV-010", "EV-118"],
  "depends_on": [],
  "conflicts_with": [],
  "detector_ref": "odooflux.rules.python.generic:keyword_in_field_call",
  "fixer_ref": "odooflux.rules.python.generic:rename_keyword",
  "params": { "call_prefix": "fields.", "keyword": "group_operator", "new_keyword": "aggregator" },
  "validation": ["syntax.python", "static.rescan"],
  "tests": { "positive": "TST-006-0xx", "negative": "TST-006-0xx", "idempotence": "TST-006-0xx" },
  "message": "Field attribute group_operator was renamed aggregator.",
  "suggestion": "Rename the keyword argument.",
  "legacy_ref": null
}
```

Constraints:
- `review_required: true` ⇒ `fixer_ref: null`.
- `maturity: FIX_ENABLED` ⇒ `fixer_ref` and all three tests are present.
- `legacy_ref` is the legacy table row (e.g. `PYTHON_RULES#2`) when the rule ports a legacy rule.

## RetiredRule

Entries with `maturity: RETIRED` and `retired_reason` record legacy dispositions in
`knowledge/compatibility/legacy_disposition.json`:
`{ "legacy_ref", "disposition": "keep|correct|retire|needs-research", "new_rule_ids": [],
"evidence": [], "gap": null, "reason" }`.

## CoreModuleList (`knowledge/compatibility/core_modules/<ver>.json`)

`{ "version": "18.0", "repository": "odoo/odoo", "revision": "<sha>", "evidence": "EV-3NN",
"modules": ["account", "base", …] }`. The list is sorted, generated by a script that reads the
official tree at the SHA.

## RiskInventoryItem

`{ "module", "class", "path", "span", "symbol", "note" }`. The classes are listed in
[research.md R-7](research.md#r-7-business-logic-inventory-req-biz-001).

## Golden fixture layout

```text
tests/golden_fixtures/<source>/<module>/              # from feature 002
tests/golden_fixtures/<source>/<module>/expected/<target>/tree/...
tests/golden_fixtures/<source>/<module>/expected/<target>/report.json
tests/golden_fixtures/rules/<rule-id>/{positive,negative}/...   # per-rule fixtures
```
