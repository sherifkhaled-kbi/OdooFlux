# Tasks: Knowledge Acquisition Pipeline

**Input**: spec.md, plan.md, research.md, data-model.md, contracts/*. **Tests**: required, written first within each task (Principle V). Test ids: `TST-011-nnn` where nnn equals the task number; cite it in the test module docstring.

## Format

`- [ ] Tnnn [P] Title (REQ ids; C: contract; F: owned files; Deps: ids; Tests: names) — Done when: ... Stop: ...`

Executor rules (Haiku-sized tasks):
1. Edit only files in `F`. Any other file is read-only. If a needed change falls outside `F`, stop and report; do not improvise.
2. Write the named tests first, see them fail, implement, see them pass. Run only the named test module (`python -m unittest tests.unit.knowledge.kap.<module> -v`), never the whole suite.
3. Stdlib only. No network, no Docker, no AI calls. No `sqlite3`.
4. Verify before editing any existing file: grep the call sites named in the task and confirm the PHASE0 facts; if they differ, stop and report.
5. Default `Stop`: all named tests pass and nothing outside `F` changed (`git status` check). Do not commit.
6. `[P]` is set only where `F` sets are disjoint from every task in the same wave (see Wave plan). No task marks a certification item done (ADR-019; REQ-KAP-043).
7. All paths under `src/odooflux/knowledge/` abbreviated `K/`; tests dirs: `U = tests/unit/knowledge/kap/`, `I = tests/integration/kap/`, `X = tests/fixtures/kap/`.

Opt-in env vars (live only, never in default runs): `ODOOFLUX_KAP_LIVE_TESTS=1` (network fetch against allow-listed URLs), `ODOOFLUX_KAP_CLONES=<dir>` (real odoo clones), `ODOOFLUX_KAP_DOCKER_TESTS=1` (Docker). Runtime variable (not a test switch): `ODOOFLUX_KB_HOME`.

New packages: `K/release/`, `K/package/`, `K/authoring/`, `K/acquisition/` (+`adapters/`), `K/extract/` (+`domains/`), `K/ledger/`, `K/candidates/`, `K/coverage/`, `K/extraction_templates/`, plus `K/pipeline.py` and CLI modules `cli/kap_*.py`. Each new package has an `__init__.py` owned by its first task.
