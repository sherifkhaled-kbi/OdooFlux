# Tests

Standard library only (`unittest`). Run everything, offline:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

| Suite | What it covers | Spec |
|---|---|---|
| `regression/` | P0 safety tests (read-only analysis, validation gate, backups, fixers, exit codes). Run against the cut-over CLI as the parity suite. | 001 |
| `unit/` | Contracts, registries, version data and graph, dependency order, discovery, planner, engine, validators, step runner, status table, report model, legacy adapter, import graph, static rules. | 003 |
| `integration/` | Workspace isolation, promotion failure, rollback, resume, analyze-only writes, CLI contract, launcher, cut-over differences, determinism, adding a version. | 003 |
| `contract/` | One sample plugin per registry kind; contract-version rejection; a raising rule. Samples are in `contract/samples/`. | 003 |
| `_support/` | Shared helpers: `digest` (tree digests), `normalize` (legacy report normalisation), `optin` (`requires_runtime`, `requires_ai`), `fixtures` (INDEX.json loader, `copy_fixture`), `cli` (`run_legacy_cli`), `p0` (P0 regression helpers). Self-tests: `unit/test_harness_*.py`. | 002 |
| `golden_fixtures/` | Fixture modules and expected outputs. `INDEX.json` lists them. `17.0/kbi_demo` with `expected/18.0` is the **PROVISIONAL** validation corpus (see below). `p0_kbi_demo_v14` is the P0 reproduction fixture. Other directories (`knowledge`, `rules`, `runtime`, `transformations`) feed specific suites. | 002, 005, 006 |
| `runtime/` | Opt-in runtime (Docker) suite. Only a placeholder gate today. Skipped unless `ODOOFLUX_RUNTIME_TESTS=1`. | 002, 008 |
| `benchmarks/` | Synthetic 300-module generator and analysis timer. The timed test runs only with `ODOOFLUX_BENCH=1`. Baseline: [BASELINE.md](benchmarks/BASELINE.md). | 003 |

Cut-over differences from the P0 script are listed in
[docs/changes/P2_CUTOVER.md](../docs/changes/P2_CUTOVER.md). The integration test
`test_cutover_differences.py` checks that each one is still observed.

## Conventions

- Each test names the requirement it covers (for example `TST-003-015`, `REQ-SAF-007`).
- Tests write only into temporary directories. The state directory is always passed explicitly.
- The root `odooflux.py` is the launcher. Tests import the package from `src/` and never from the root.

## Provisional validation corpus

`golden_fixtures/17.0/kbi_demo/expected/18.0` was produced by running the current engine (`tools/update_expectations.py`),
not by an independent reviewer. It tests framework mechanics (byte-exact reproduction, idempotence, SC-005, rejection of
unsupported targets). It is **not** approved migration truth. Each of `17.0/`, `17.0/kbi_demo/expected/` and
`17.0/kbi_demo/expected/18.0/` carries a `PROVISIONAL.md`, and `INDEX.json` has `"authority": "PROVISIONAL"`;
`integration/test_provisional_corpus.py` fails if any of those labels is removed or changed to an approval.
Regenerate after an intended engine or report change: `PYTHONPATH=src python3 tools/update_expectations.py --force`,
then review the diff.

## Opt-in flags

| Flag | Enables |
|---|---|
| `ODOOFLUX_RUNTIME_TESTS=1` | tests decorated `@requires_runtime` (Docker) |
| `ODOOFLUX_AI_TESTS=1` | tests decorated `@requires_ai` |
| `ODOOFLUX_BENCH=1` | timed benchmarks |

Without a flag the test is skipped and the reason names the flag.

## Fixture layout and ID conventions

- Test IDs: `TST-<feature>-<nnn>` in docstrings. Finding IDs (`F-SAFE-1`, `F-PY-2`, ...) appear in the docstring of the
  regression test that guards them.
- Fixture entry fields (`INDEX.json`): `id`, `source_version`, `module`, `path`, `targets`, `evidence`, `findings`,
  `authority`, `layout`, `input_digest`. Golden layout: `<source>/<module>/expected/<target>/{tree/,report.json}`.
  `golden_fixtures/.gitattributes` sets `* -text` so bytes are never rewritten.
- `integration/test_fixture_validity.py` validates every entry; `integration/test_zz_input_immutability.py` checks the
  recorded `input_digest` of every fixture.

## Adding a regression test

1. Write the test with the finding ID in the test or class docstring.
2. Add a row to `regression/INDEX.md` (`path::Class::method`). `regression/test_regression_index.py` checks that the
   test exists and cites the ID.
3. Rule coverage tags: put `rule:<category>:positive|negative|idempotence` in a docstring; the report
   `tests/rule_coverage.txt` is regenerated by `unit/test_rule_coverage_report.py` (report only).
